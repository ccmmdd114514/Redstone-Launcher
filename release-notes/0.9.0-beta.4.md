# 红石启动器 0.9.0-beta.4 发布说明

> Beta 测试版 · 2026-10-03
> 下载：见 Releases 页面（预编译包待 CI 产出后补充；本版暂无本地编译出的 exe）

## 相较于上一版的改进

1. **此前**：双击 `redstone.exe` 不带任何参数时，只打印帮助就退出，黑窗口一闪而过，
   普通用户根本无从下手。
   **现在**：双击（无参数）直接进**交互模式**——黑窗口常驻、提示符 `redstone>`，
   键盘敲命令循环执行，直到 `exit` / `quit` / `q` 退出；首次真正做到了「双击即用」。

2. **此前**：命令行只在外部终端以 `redstone <子命令>` 形式使用，没有内置交互入口。
   **现在**：交互模式与外部命令行**共用同一套派发逻辑**（`run_command`），所有子命令
   实现一行未改，两种入口行为完全一致，回归风险极低。

3. **此前**：交互场景下的参数切分依赖 clap 的 `split_whitespace`，带空格的玩家名需要
   用户自己注意转义。
   **现在**：交互模式内置零依赖的引号感知 `split_args`，
   `launch 1.21.8 --name "My Player"` 能正确把 `My Player` 当成一个整体，并配了 5 条
   单元测试覆盖基础切分、双引号、单引号、多余空格、含 `-` 的标志。

4. **此前**：外部命令行被当作唯一正式入口。
   **现在**：明确把外部命令行 `redstone <命令>` 定位为「传统模式 / 彩蛋」，
   承诺保留到 1.0 正式版，两种入口长期并存、行为一致。

## 本版本已知 bug 与未解决项

### 本版本新增问题

1. **交互模式未经编译验证（最高优先）**
   - 现象：本机 `cargo build --release` 卡在 dlltool 死锁，beta.4 的 exe 尚未产出，
     交互模式目前只做了代码 review，没有实机双击验证过。
   - 影响：REPL 循环、引号解析、banner 文案是否符合预期，需等 CI 通或干净机器编译后实测。
   - 规避：暂不要用双击交互；先用外部命令行 `redstone <命令>`。
   - 计划修复版本：下一个能编译的版本（CI 一通即验）。

2. **交互模式下网络长任务会阻塞输入**
   - 现象：`install` 下载期间无法敲下一条命令，必须等它跑完。
   - 影响：仅体验层面，不影响正确性。
   - 规避：长任务另开一个实例，或等它跑完再敲。
   - 计划修复版本：暂不修（交互模式本就是顺手入口，重度使用仍走外部命令行）。

### 上一版继承未修

1. **paths.rs 脱敏改动未经编译验证**：`dev_root()` / `bundled_java_root()` 改为从
   `LOCALAPPDATA` / `USERPROFILE` 环境变量派生，任意 Windows 用户 clone 即用，但本机
   编不出 exe，没跑过 `redstone doctor` 复核。
2. **build.rs 图标接入未经编译验证**：exe 是否真带红石方块图标、版本信息是否写入资源段，
   需 CI 的 pwsh 断言步骤确认。
3. **新增依赖 winresource 需联网**：`build.rs` 会调 gnu 资源编译器，CI 有网可拉；
   本机离线编不过时这是已知障碍之一。
4. **gnu 资源编译器未实测**：`winresource` 在 windows-gnu 下的行为未在真实环境跑过。
5. **老版本兼容未验证**：1.12.2（Java 8）/ 1.16.5 等新旧分支未实机跑通过。
6. **离线 UUID 尚未对齐 HMCL/PCL2**：当前用 `uuid5("offline:<昵称>")` 派生，与主流
   启动器的离线 UUID 算法是否一致未核对。
7. **CI 尚未启用**：`.github/workflows/build.yml` 已写好但推不上去（PAT 缺 `workflow`
   scope），云端编译未跑，所有「需编译验证」项都卡在这里。
