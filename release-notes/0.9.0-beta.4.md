## 相较于上一版的改进

1. **此前**：双击 `redstone.exe` 不带任何参数时，只打印帮助就退出，黑窗口一闪而过，
   普通用户根本无从下手。
   **现在**：双击（无参数）直接进**交互模式**——黑窗口常驻、提示符 `redstone>`，
   键盘敲命令循环执行，直到 `exit` / `quit` / `q` 退出；首次真正做到了「双击即用」。

2. **此前**：命令行只在外部终端以 `redstone <子命令>` 形式使用，没有内置交互入口。
   **现在**：交互模式与外部命令行**共用同一套派发逻辑**（`run_command`），所有子命令
   实现一行未改，两种入口行为完全一致，回归风险极低。

3. **此前**：交互场景下的参数切分依赖 clap 的 `split_whitespace`，带空格的玩家名需要
   用户自己注意转义。
   **现在**：交互模式内置零依赖的引号感知 `split_args`，
   `launch 1.21.8 --name "My Player"` 能正确把 `My Player` 当成一个整体，并配了 5 条
   单元测试覆盖基础切分、双引号、单引号、多余空格、含 `-` 的标志。

4. **此前**：外部命令行被当作唯一正式入口。
   **现在**：明确把外部命令行 `redstone <命令>` 定位为「传统模式 / 彩蛋」，
   承诺保留到 1.0 正式版，两种入口长期并存、行为一致。

5. **此前**：beta.3 及更早版本在本机 `cargo build --release` 卡在 dlltool 死锁，
   产不出可执行文件，所有改动都停留在源码层面。
   **现在**：改用 GitHub Actions 云端编译（windows-latest，环境干净无安全软件干扰），
   首次产出了带图标与版本信息的正式可执行文件。

## 本版本已知问题与未解决项

### 本版本新增问题

1. **交互模式 REPL 未做实机双击验证**
   - 现象：exe 已产出，但本轮仅运行了 `--version` 与 `doctor` 两条非交互路径，
     REPL 的启动横幅、提示符循环、`help` 命令列表尚未实机点验。
   - 影响：不影响传统命令行使用；交互模式体验可能存在未预期问题。
   - 规避：暂时改用传统命令行 `redstone <命令>`。
   - 计划修复版本：0.9.0-beta.5（实机点验并修复）。

2. **二进制内含构建机源码路径**
   - 现象：exe 字符串中可检索到 CI 构建机的依赖源码路径
     （形如 `C:\Users\runneradmin\.cargo\registry\...`），来源为 Rust 的 panic 调试信息。
   - 影响：仅为构建环境信息，不含任何用户隐私，不影响功能与安全。
   - 规避：无需规避。
   - 计划修复版本：0.9.0-beta.5（启用 release 配置的路径裁剪）。

### 上一版继承未修

1. **交互模式下网络长任务会阻塞输入**：`install` 下载期间无法敲下一条命令，
   必须等其跑完。仅影响体验，不影响正确性。计划修复版本：待定。
2. **老版本兼容未验证**：1.12.2（Java 8）、1.16.5 等新旧分支未实机跑通。
   计划修复版本：0.9.0-beta.5。
3. **离线 UUID 未对齐 HMCL / PCL2**：当前用 `uuid5("offline:<昵称>")` 派生，
   与主流启动器的离线 UUID 算法是否一致尚未核对。计划修复版本：0.9.0-beta.5。
4. **无 JRE 自动下载**：缺少对应 Java 版本时只提示，不自动下载。计划修复版本：待定。
5. **仅支持离线账号**：微软 OAuth 正版登录与 LittleSkin 尚未实现。计划修复版本：待定。
6. **不支持模组加载器**：Fabric / NeoForge / Forge 与整合包均未支持。计划修复版本：M3。
