# 0.9.0-beta.3（Beta 测试版）

发布日期：2026-10-03

版本类型：**Beta 测试版**。本版本为项目**首次给可执行文件带上图标**，
同时补齐英文说明文档。命令行形态与 beta.2 一致，不含图形界面。

## 相较于上一版的改进

### 新增

- **exe 带图标了**：红石方块图标已嵌入 `redstone.exe` 的 Windows 资源段。
  此前 beta.1 / beta.2 的 exe 是 Windows 默认的空白可执行文件图标，
  现在资源管理器、任务栏、开始菜单里显示的都是红石方块。
  图标内含 16/24/32/48/64/128/256 七档尺寸，小尺寸与高分屏缩放都不糊。
- **文件属性里有版本信息了**：文件描述、产品名、文件版本号、版权信息随图标
  一并写入资源段，可在文件属性的「详细信息」页直接看到。
- **新增 `tools\make-icons.py`**：一条命令从任意源 PNG 生成 exe 用的多档
  `.ico` 与文档用的大图 `.png`，换图标不必手工拼装。
- **新增 `assets\icon.png`（512×512）**：供 GitHub 仓库头像、README 配图使用。

### 改进

- 此前：仓库只有中文说明，英文用户打开 GitHub 首页看到的是一整页中文，
  只能自己猜着看，或干脆走人。现在新增 `README.en.md` 完整英文版
  （系统要求、下载直链、SHA-256 校验、构建步骤含 dlltool 坑、命令参考表、
  实现要点、路线图、合规声明、许可证），与中文版逐节对齐。
- 此前：中文 README 没有通往英文版的入口。现在开头第二行即为
  `🌐 Looking for the English version? [Click here →](README.en.md)`，
  英文版顶部也带 `English | 简体中文` 导航，两边互跳。

### 变更

- 版本号由 `0.9.0-beta.2` 抬至 `0.9.0-beta.3`。
- `Cargo.toml` 新增构建依赖 `winresource 0.1`，并新增 `build.rs`。
- `build.rs` 中图标资源编译失败**只打印警告不中断构建**（`cargo:warning=`），
  避免图形资源的问题把整个编译流程卡死。

## 本版本已知 bug 与未解决项

### 本版本新增问题

1. **图标改动未经任何编译验证**：本机 `windows-sys`（raw-dylib）在链接期调用
   `dlltool` 时报 `Permission denied`，项目自 beta.2 起就无法产出 exe，
   因此 `build.rs`、`winresource` 依赖与图标资源是否真的能编过**尚未实测**。
   → 影响：beta.3 可能仍拿不出可用的 exe，也可能因 `winresource` 引入新的
   构建失败。
   → 当前规避：`build.rs` 内的图标编译失败路径只警告不中断，最坏情况退回
   无图标构建，其余功能不受影响。
   → 计划：dlltool 问题解决后第一时间全量构建并核对 exe 图标。

2. **新增构建依赖需要联网拉取**：`winresource 0.1` 首次构建时须从 crates 源
   拉取（本机走清华 sparse 源），离线环境下无法从零构建。
   → 规避：`Cargo.lock` 已入库，锁定版本后在联网机器上先 `cargo fetch`。

3. **gnu 目标下的资源编译器未验证**：`winresource` 在 Windows 上需要
   `windres` 或 `rc.exe`。本机 `C:\mingw64\bin\windres.exe` 存在，
   Rust 工具链亦自带 `llvm-rc`，理论可用，但实际取哪一个未验证。

### 上一版继承未修

1. `dist\redstone.exe` 仍是 beta.1 的程序，beta.2 / beta.3 的 exe 均未产出
   → 卡在 dlltool，已停止盲目重试
2. `src\paths.rs` 为开源做的脱敏改造（`DEV_ROOT` 等改为读 `LOCALAPPDATA` /
   `USERPROFILE` 派生）**同样未经编译与运行验证**
   → 计划：编译通过后第一件事跑 `redstone doctor`，确认仍能识别用户级 JDK
3. `remove` 判据只认实例目录：版本本体在、实例目录丢失时会提示「实例不存在」
4. 仅验证过 1.21.8 与 1.21.11，1.12.2 / 1.16.5 等老版本未实测
5. 无进程锁：重复启动同一版本会因原生库目录被占用而失败
6. 无 JRE 自动下载：缺少所需 Java 版本时只提示，不自动下载
7. 下载无失败阈值：源异常时按重试次数硬扛到底，不提前中止
8. 资源索引（`assetIndex`）下载后未校验 sha1
9. 仅支持离线账号；微软正版登录与 LittleSkin 尚未实现
10. 不支持模组加载器（Fabric / NeoForge / Forge）与整合包

## 验证情况

验证环境：Windows 11（内部版本 26200），Python 3.14 + Pillow（仅用于生成图标）。

| 验证项 | 结果 |
| --- | --- |
| 图标源图 | `Block_of_Redstone_JE4_BE2.png`，300×300 RGBA |
| `assets\icon.png` | 生成成功，512×512，96,833 字节 |
| `assets\icon.ico` | 生成成功，含 16/24/32/48/64/128/256 七档，64,531 字节 |
| 图标生成脚本 | `tools\make-icons.py` 实跑通过，输出尺寸与体积均符合预期 |
| `build.rs` 接入 | 已写入，**未经编译验证**（见「本版本新增问题」第 1 条） |
| exe 图标实际显示 | **未验证**：beta.2 的 exe 仍编不出来，无从检查 |

> **总结**：本版本的**图标素材已经就绪、接入代码已经就绪**，
> 但**最终效果没有实测**。诚实地说，现在还不能保证你拿到一个带图标的 exe。
